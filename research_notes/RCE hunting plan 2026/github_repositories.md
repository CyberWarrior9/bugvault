# Four GitHub repositories for an authorized RCE hunting plan (20 Nov 2026)

## Which exactly four repositories provide complementary guidance?

### Takeaway
Select one source for each function: OWASP WSTG for test structure, CodeQL for source-to-sink reasoning, PayloadsAllTheThings for exploit-class *taxonomy*, and Semgrep community rules for source-code detection/triage. These are planning references, not evidence that a target is exploitable.

### Cited Findings
- **Structured methodology — [OWASP/wstg](https://github.com/OWASP/wstg).** The official guide's [injection index at the reviewed commit](https://github.com/OWASP/wstg/blob/86b4263598d05d85fb0ea1f0d08f06e7e46fd26d/document/4-Web_Application_Security_Testing/07-Injection/README.md) identifies `11-Code_Injection.md`, `12-Command_Injection.md`, `18-Server-side_Template_Injection.md`, and `23-Insecure_Deserialization.md` under `document/4-Web_Application_Security_Testing/07-Injection/`. Strength: a common, scenario-based test vocabulary. Limit: the [README](https://github.com/OWASP/wstg/blob/86b4263598d05d85fb0ea1f0d08f06e7e46fd26d/README.md) distinguishes in-progress v5.0 content from stable v4.2 and recommends versioned citations; neither version confirms a specific finding.
- **Sink/dataflow analysis — [github/codeql](https://github.com/github/codeql).** The pinned tree contains [JavaScript CWE-078 command-injection path queries](https://github.com/github/codeql/tree/aafa7deeff16c1e3c4e356eabec46cbca2dc09e3/javascript/ql/src/Security/CWE-078), [Python CWE-078 queries](https://github.com/github/codeql/tree/aafa7deeff16c1e3c4e356eabec46cbca2dc09e3/python/ql/src/Security/CWE-078), and C# [CWE-094 code-injection](https://github.com/github/codeql/tree/aafa7deeff16c1e3c4e356eabec46cbca2dc09e3/csharp/ql/src/Security%20Features/CWE-094) / [CWE-502 deserialization](https://github.com/github/codeql/tree/aafa7deeff16c1e3c4e356eabec46cbca2dc09e3/csharp/ql/src/Security%20Features/CWE-502) queries. Strength: [path queries describe source-to-sink flow](https://codeql.github.com/docs/writing-codeql-queries/about-codeql-queries/), useful if the program supplies authorized source. Limit: query coverage depends on language/framework modeling and access to analyzable code; a path is a lead, not demonstrated execution.
- **Exploit-class reference — [swisskyrepo/PayloadsAllTheThings](https://github.com/swisskyrepo/PayloadsAllTheThings).** Its pinned tree indexes [`Command Injection/`](https://github.com/swisskyrepo/PayloadsAllTheThings/tree/08ea40e77db3f42ef8f20c65196f3936a19b6c86/Command%20Injection), [`Server Side Template Injection/`](https://github.com/swisskyrepo/PayloadsAllTheThings/tree/08ea40e77db3f42ef8f20c65196f3936a19b6c86/Server%20Side%20Template%20Injection), and [`Insecure Deserialization/`](https://github.com/swisskyrepo/PayloadsAllTheThings/tree/08ea40e77db3f42ef8f20c65196f3936a19b6c86/Insecure%20Deserialization). Strength: cross-class breadth for categorizing a suspected primitive. Limit: its [root README](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/08ea40e77db3f42ef8f20c65196f3936a19b6c86/README.md) says chapters include exploit payloads and Burp Intruder files; **do not copy, fetch for this note, or dispatch those materials**. Treat chapter claims as leads requiring primary-source and target-specific checks.
- **Detection/triage — [semgrep/semgrep-rules](https://github.com/semgrep/semgrep-rules).** Pinned examples include [`python/django/security/injection/command/subprocess-injection.yaml`](https://github.com/semgrep/semgrep-rules/blob/a5ad1714f00c9f7fde980cab0ea1d6dc6d414fd2/python/django/security/injection/command/subprocess-injection.yaml), [`java/lang/security/audit/command-injection-process-builder.yaml`](https://github.com/semgrep/semgrep-rules/blob/a5ad1714f00c9f7fde980cab0ea1d6dc6d414fd2/java/lang/security/audit/command-injection-process-builder.yaml), and [`csharp/lang/security/insecure-deserialization/binary-formatter.yaml`](https://github.com/semgrep/semgrep-rules/blob/a5ad1714f00c9f7fde980cab0ea1d6dc6d414fd2/csharp/lang/security/insecure-deserialization/binary-formatter.yaml). Strength: language/framework-specific review leads for code the operator may inspect. Limit: its [README](https://github.com/semgrep/semgrep-rules/blob/a5ad1714f00c9f7fde980cab0ea1d6dc6d414fd2/README.md) distinguishes Community Edition rules from proprietary Pro rules with deeper cross-file/dataflow capability; a rule hit is not an RCE proof.

### Inferences
- Use WSTG to enumerate *applicable* classes, CodeQL to trace any authorized source into execution-like sinks, Semgrep to prioritize independent code-review leads, and PayloadsAllTheThings **only for class names and reference trails**. Compare leads to the actual reachable operation and its controls before considering live validation.

### Gaps
- No selected source was evaluated against a BugVault campaign, and no repository's alerts or class descriptions were benchmarked for false positives here. The CodeQL repository's full recursive tree response was truncated; the cited language directories were checked individually.

## How recent and reusable are the selected sources as of 20 Nov 2026?

### Takeaway
All four have dated 2026 repository activity, but a recent repository commit does not imply that each RCE chapter or rule was recently security-reviewed. Licensing must be checked separately for content, rules, and executable tooling.

### Cited Findings
- **WSTG:** a [20 Nov 2026 commit](https://github.com/OWASP/wstg/commit/86b4263598d05d85fb0ea1f0d08f06e7e46fd26d) published checklists *by bot*; the command-injection file had a [13 Nov 2026 formatting edit](https://github.com/OWASP/wstg/commit/241a58ec77107ca556cc84e16e1210ff630136a8), not a demonstrated technical update. Its [README](https://github.com/OWASP/wstg/blob/86b4263598d05d85fb0ea1f0d08f06e7e46fd26d/README.md) labels the guide CC BY-SA 4.0: cite/attribute and do not transplant adapted guide prose into BugVault's MIT materials without checking share-alike obligations.
- **CodeQL:** the [20 Nov 2026 commit](https://github.com/github/codeql/commit/aafa7deeff16c1e3c4e356eabec46cbca2dc09e3) explicitly addresses Java command-injection detection. The [repository README](https://github.com/github/codeql/blob/aafa7deeff16c1e3c4e356eabec46cbca2dc09e3/README.md) calls its libraries/queries MIT but says the **CLI/engine is separately licensed** and a separate commercial license is needed for closed-source analysis; do not infer CLI rights from the MIT repo.
- **PayloadsAllTheThings:** its [30 Oct 2026 commit](https://github.com/swisskyrepo/PayloadsAllTheThings/commit/08ea40e77db3f42ef8f20c65196f3936a19b6c86) shows repository activity; the command-injection chapter's [22 Apr 2026 edit](https://github.com/swisskyrepo/PayloadsAllTheThings/commit/e961fef231d8327bae83b563fab50aec2e6b77c0) is described as reference-date/format maintenance, not technical validation. The [MIT license](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/08ea40e77db3f42ef8f20c65196f3936a19b6c86/LICENSE) names Swissky and requires retaining copyright/license notice in copies or substantial portions; no content is copied here.
- **Semgrep rules:** the [10 Nov 2026 commit](https://github.com/semgrep/semgrep-rules/commit/a5ad1714f00c9f7fde980cab0ea1d6dc6d414fd2) changes a Pro interfile test, **not** the cited Python command rule; that rule's latest returned commit is [15 Jan 2026](https://github.com/semgrep/semgrep-rules/commit/46a0ecfdf78f86a6409677c58417f845ef9eae9a), an OWASP mapping change. The repository [README](https://github.com/semgrep/semgrep-rules/blob/a5ad1714f00c9f7fde980cab0ea1d6dc6d414fd2/README.md) and [Semgrep Rules License v1.0](https://semgrep.dev/legal/rules-license/) distinguish the rules from the open-source engine: rules are restricted to one's own internal business use, not redistribution or service provision. Link and paraphrase; do not incorporate rule text into a redistributable BugVault pack without rights review.
- **Not selected:** [HackTricks-wiki/hacktricks](https://github.com/HackTricks-wiki/hacktricks) overlaps the exploit-reference role; its [current FAQ/license statement](https://github.com/HackTricks-wiki/hacktricks/blob/master/src/welcome/hacktricks-values-and-faq.md) says “all rights reserved unless otherwise specified,” discusses third-party material, and directs commercial-use inquiries to the author. This makes it a less clean reuse choice than the four above; it is **not a fifth recommendation**.

### Inferences
- Pin a commit and a versioned WSTG scenario when writing a durable campaign plan; assess Semgrep-rule and CodeQL-CLI permissions before any code scan. A repo's dated commit establishes maintenance activity, not the validity of a particular detection or technique.

### Gaps
- No license opinion on a particular commercial deployment is offered; the operator must review the controlling terms and program permission. No claim was made that a cited chapter/rule's *security content* was comprehensively refreshed in 2026.

## How should these inform a responsible plan rather than an RCE claim?

### Takeaway
Keep the sources as an offline decision aid. Start from written authorization and exact sinks; validate only with separately approved, bounded, owned effects and independent controls—not reference payloads or static-alert counts.

### Cited Findings
- WSTG itself advises [versioned scenario identifiers](https://github.com/OWASP/wstg/blob/86b4263598d05d85fb0ea1f0d08f06e7e46fd26d/README.md); CodeQL distinguishes [simple alerts from source-to-sink paths](https://codeql.github.com/docs/writing-codeql-queries/about-codeql-queries/); Semgrep explicitly distinguishes [community and proprietary cross-file capabilities](https://github.com/semgrep/semgrep-rules/blob/a5ad1714f00c9f7fde980cab0ea1d6dc6d414fd2/README.md); PayloadsAllTheThings explicitly bundles [operational chapter and Intruder material](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/08ea40e77db3f42ef8f20c65196f3936a19b6c86/README.md). None of these facts establishes target-side execution.

### Inferences
- A BugVault plan can record candidate input → parser/interpreter/command sink → observed output or side effect → distinct negative control, with actor/resource/cleanup and exact authorization for any later live step. Keep SSTI evaluation, unsafe deserialization, command construction, and actual OS-code execution as **separate evidence rungs**; never promote from a tool finding, callback, or taxonomy label alone.

### Gaps
- No target, account, codebase, payload, or live execution was inspected; this note neither requests nor authorizes a scan or RCE test. Only top-level READMEs, non-payload conceptual/index/license pages, and repository metadata were fetched; exploit-chapter contents and rule bodies were not fetched for this note.
