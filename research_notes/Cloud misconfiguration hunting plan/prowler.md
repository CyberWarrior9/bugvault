# Prowler: public-source research for BugVault cloud-misconfiguration hunting

Research/access date: **2026-11-16**. Research only: no installation, Prowler execution, credentials, cloud accounts, resource queries or target tests. Only `prowler-cloud/prowler` GitHub pages, its raw files and GitHub API metadata were fetched. All technical source-file links below are pinned to the researched default-branch commit. Statements labelled **Fact** describe the retrieved project; **Inference / recommendation** is an independently written BugVault design proposal, not a Prowler claim or implemented BugVault feature. No upstream payloads, remediation code or substantial licensed prose are reproduced.

## 1. What is the current project, provider breadth and trustworthy provenance?

### Takeaway

Prowler is an actively maintained cloud-security assessment platform with CLI, local-server/API/UI and several external-tool adapters; it is not merely an AWS checklist. Use a pinned release/schema as an optional source of owner-authorized configuration observations, not as authorization, exploit execution or automatic finding confirmation. ## 2. What do findings mean, what permissions are required, and what can mislead a hunter?

### Takeaway

The useful unit is a versioned **check + exact cloud resource + observed configuration + scan context**, not a checklist title or generic severity. Prowler has rich normalized output, but an assessment result is not a signed request transcript, an effective-authorization proof or demonstrated business impact; some optional features perform writes, read sensitive content or validate credentials against external APIs. [Finding model](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/finding.py#L27-L61); [fixers](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/fixer.mdx); [secret validation](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/developer-guide/secret-scanning-checks.mdx#L100-L108)

### Cited Findings

**Metadata, evidence and outputs**

- **Fact — check model:** `CheckMetadata` includes provider/check ID and aliases, service/subservice, resource type/group, static severity, description, risk, categories, dependency/related-check lists, notes, compliance and remediation recommendations/code fields. Severity values are critical/high/medium/low/informational. These fields describe a control and its expected risk; they do not assert that its risk was realized on an audited resource. [Model source](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/check/models.py); [metadata-writing guidance](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/developer-guide/check-metadata-guidelines.mdx)
- **Fact — per-result model:** `Check_Report` carries status/status explanation, resource data/details/tags, mute state and an optional structured `raw` dictionary, which is normally empty. Provider-specific reports add AWS ARN/region, Azure subscription/location, or GCP project/location. `Finding` normalizes auth method, timestamp, account and organization labels, check metadata, finding UID, resource UID/name/metadata/details/tags, region/partition, compliance, version and `raw`. [Check report source](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/check/models.py); [normalized fields](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/finding.py#L27-L61)
- **Fact — UID caveat:** The normalized finding UID is built from provider, check ID, account UID, region and **resource name**, with IaC line-range handling. Missing resource names/UIDs are logged. Do not assume a finding UID by itself is an immutable, collision-free resource identity or a unique observation across scans. [UID construction](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/finding.py#L575-L598)
- **Fact — export formats:** Reporting docs describe default CSV and JSON-OCSF; supported formats include HTML, AWS-only JSON-ASFF, and IaC-only SARIF. Native older JSON is deprecated. OCSF represents a Detection Finding, mapping the check ID to `metadata.event_code`, scanner verdict to `status_code`, resource identity to `resources[].uid`, and version to product metadata; it also adds an `unmapped.scan_id`. [Reporting formats/mappings](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/reporting.mdx); [OCSF implementation](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/ocsf/ocsf.py#L85-L186)
- **Fact — status is not one field:** The enum defines PASS, FAIL, MANUAL and MUTED. In CSV a muted result retains its original verdict with a separate mute flag; in OCSF the lifecycle status becomes Suppressed while the original check verdict is represented separately. An OCSF `status: New` is therefore not equivalent to `FAIL`. [Status enum](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/common.py#L23-L27); [mute semantics](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/mutelist.mdx#mutelist-option-behavior); [OCSF status mapping](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/ocsf/ocsf.py#L321-L335)
- **Fact — resource-data privacy:** Reports serialize resource metadata, and `redact_sensitive_fields` masks fields declared in individual models' `sensitive_fields`; it is not a generic scan of all arbitrary strings for secrets. The reporting docs contain older illustrative output with environment values, so examples must not be treated as a guarantee of current complete redaction. [Redactor](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/check/redact.py#L17-L43); [OCSF resource serialization](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/ocsf/ocsf.py#L128-L155); [reporting example](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/reporting.mdx#json-ocsf)

**Inventory, false positives and missing coverage**

- **Fact — quick inventory is limited:** Documented only for AWS, defaulting to all regions; uses Resource Groups Tagging API, so it only includes resources with current/past tags, except IAM and S3 which use separate boto3 calls. It exports CSV/JSON. This cannot establish complete cloud inventory. [Quick inventory and caveat](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/quick-inventory.mdx)
- **Fact — policy-centric escalation heuristic:** The IAM helper explicitly documents that it does not account for resource constraints, conditions, SCP restrictions or transitive paths, and checks policies rather than service-role permission context. The managed-policy check examines custom policies and normally skips unattached policies. The helper matches expanded action combinations against effective allowed actions. A scanner FAIL therefore does not demonstrate that a particular principal can escalate. [Documented limits](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/aws/services/iam/lib/privilege_escalation.py#L6-L15); [matching logic](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/aws/services/iam/lib/privilege_escalation.py#L466-L517); [check scope](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/aws/services/iam/iam_policy_allows_privilege_escalation/iam_policy_allows_privilege_escalation.py)
- **Fact — permissive setting is not resource exposure:** The Azure blob check tests the account's `allow_blob_public_access` boolean; it does not itself attempt anonymous retrieval or inspect a specific object. AWS S3 public-access logic inspects account/bucket blocks, ACLs and policy; it can emit a single **account-level PASS** rather than one result for each bucket. GCP cloud-storage emits **MANUAL**, not PASS, when bucket IAM is unreadable; its service labels public membership by presence of `allUsers`/`allAuthenticatedUsers` in IAM bindings. [Azure code](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/azure/services/storage/storage_blob_public_access_level_is_disabled/storage_blob_public_access_level_is_disabled.py); [S3 code](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/aws/services/s3/s3_bucket_public_access/s3_bucket_public_access.py); [GCP check](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/gcp/services/cloudstorage/cloudstorage_bucket_public_access/cloudstorage_bucket_public_access.py); [GCP collector](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/gcp/services/cloudstorage/cloudstorage_service.py#L26-L39)
- **Fact — intentional configuration and suppressions:** Mutelist docs expressly describe intentional public website buckets and application ports. Matching uses account/check/region/resource and optional tag constraints, and AWS has a default mutelist. A muted item remains an observation, not a proven false positive or proof of safety. [Mutelist source](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/mutelist.mdx)
- **Fact — checks evolve:** Release 5.50.0 documents an Azure NSG Any-protocol false-negative correction, omission of unsupported DNSSEC evaluation on private GCP zones, and a GCP CSEK retirement-related finding explanation. It also documents a secret-confidence threshold with a precision/coverage tradeoff. These are project release claims, not independently tested cloud-provider facts in this research. [Release notes](https://github.com/prowler-cloud/prowler/releases/tag/5.50.0)

### Inferences

- Store **scanner severity**, **scanner verdict**, **lifecycle/mute state**, **BugVault hypothesis state**, **proven impact** and **assessed reportability** independently. An alert title/risk paragraph, suppressed status, `is_verified`, graph edge or missing row must not promote a finding. [Model/mapping basis](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/ocsf/ocsf.py#L85-L186)
- A complete permission failure is often visible as MANUAL, but do not assume every provider/check handles all failures that way. Preserve scan logs and declared/executed/skipped/error denominators; distinguish resource absent, not selected, API disabled, access denied, filtered, muted and evaluated-safe. [Explicit GCP MANUAL handling](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/gcp/services/cloudstorage/cloudstorage_bucket_public_access/cloudstorage_bucket_public_access.py); [secret preparation failure guidance](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/developer-guide/secret-scanning-checks.mdx#L35-L37)
- Scanner filters and muting are not a scope sandbox: output suppression is not proof that underlying services were never queried. A later live plan must review selected checks **and their collectors/dependencies**, exact cloud API actions, retries, regions and all cross-account enumeration. Cloud SDK operations cannot be classified by HTTP verb alone; a POST may be a read RPC and a read-labelled action may reveal credentials. [S3 collector dependencies](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/aws/services/s3/s3_bucket_public_access/s3_bucket_public_access.py); [permissions discrepancy](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/permissions/prowler-additions-policy.json); [mutelist output semantics](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/mutelist.mdx)

### Gaps

- No proof that Prowler enforces BugVault host scope, cloud resource grants, shared request budgets, pacing or finding lifecycle. No reviewed general-purpose hard API-attempt cap or full collector-call map. **Do not present scanner-native filters, muting or read-only IAM policies as those enforcement mechanisms.** [Available documented execution selection](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/misc.mdx); [permission source](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/permissions/prowler-additions-policy.json)
- No audit of all model `sensitive_fields` declarations, third-party dependencies or every output serializer. Treat exports/logs/graph data as private until independently redacted; do not promise complete secret stripping from source snippets. [Redactor scope](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/check/redact.py#L17-L43)

## 3. How should BugVault turn initial hints into hypotheses, controlled validation and deeper permitted impact?

### Takeaway

**Design proposal, not an implemented feature:** use Prowler as one input to an offline, evidence-linked cloud hypothesis ledger. Investigate each concrete trust boundary with distinct owner/low-privilege/anonymous contexts, controlled marker resources and a negative control; continue along supported, explicitly authorized edges as far as needed, without an arbitrary depth ceiling or automatic exploitation/secret harvesting. The need for independent principal/resource-context validation follows directly from the detector limitations and setting-versus-exposure examples above. ### Inferences

**A. When and where to use each lane**

1. **External-only bounty lane:** Start from captured in-scope application/storage/identity references and owner-supplied public-source evidence. Convert a cloud hostname, bucket reference, resource ID, public-access hint or secret-looking **name/location** into a resource-ownership question, not an account-wide scan. No cloud credentials means no assumption that authenticated Prowler assessment is available or allowed. A domain grant does not automatically grant its backing cloud account or every resource sharing that provider. Prowler's documented credential/permission requirements make an owner-assisted lane a distinct capability, not a workaround. [AWS requirements](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/providers/aws/authentication.mdx#required-permissions)
2. **Owner-assisted assessment lane:** Import an authorized operator's fresh version-pinned Prowler export with its exact selected accounts/projects/subscriptions, principals, regions, checks, errors and suppressions. Reconcile it with the intended inventory before ranking. A future operator-run assessment needs a separate standing plan, reviewed action/content permissions, all-channel request and cost budgets, retry accounting, safe output destination and stop/cleanup owner. All accessible subscriptions or organization fallbacks are specifically hazardous defaults. [Azure scan breadth](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/providers/azure/authentication.mdx#subscription-scope-permissions); [GCP organization prerequisite/fallback](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/providers/gcp/authentication.mdx#service-account-key-file)
3. **Artifact/IaC lane:** Use approved repository/image artifacts as separate, deployment-bound hints. Preserve repository commit/file/line or image digest and map them to an actual deployment before claiming live cloud exposure; IaC SARIF is explicitly file/line-oriented and not a live-resource permission test. [IaC SARIF semantics](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/reporting.mdx#sarif-iac-only)
4. **Reopen after change:** Refresh hypotheses after a resource policy/identity/network change, deployment, new owned account/role context, check-version change or error-resolution event. Retain prior scan observations rather than silently replacing a FAIL/MANUAL with a newer row. Version-specific fixes and UID construction make observation history important. [5.50.0 corrections](https://github.com/prowler-cloud/prowler/releases/tag/5.50.0); [UID construction](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/finding.py#L575-L598)

**B. Minimal independent data model / import contract**

Recommended **offline** records (new design; do not claim these commands/tables exist):

- `source_receipt`: source URL, access date, pinned repository/release/check versions, exporter version, file SHA-256, schema version, scan identity label, start/end, declared scope, check selections, exclusions/mutelist hash and permission/error summary. Retain the original private artifact separately from its redacted normalized derivative. This extends the actual Finding/version fields rather than inventing raw provider-response receipts. [Finding fields](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/finding.py#L27-L61)
- `resource_context`: provider + partition + owner account/tenant/project/subscription + canonical resource UID/type + region/location + environment + supplied test-owner label. A name/domain/tag alone is insufficient identity/ownership proof. Keep upstream UID as provenance, not the sole dedup key. [Provider-to-output mapping](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/reporting.mdx#csv-headers-mapping)
- `cloud_observation`: check ID, exact evaluated scope (account aggregate or per-resource), verdict, lifecycle/mute status, scanner severity, redacted machine-readable condition, observed time and receipt. Prefer structured evidence over parsing status prose, but do not presume optional `raw` survives every export. Preserve distinct observations by scan/time and deduplicate only repeated imports of the same artifact. [Report model](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/check/models.py); [S3 account aggregation](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/aws/services/s3/s3_bucket_public_access/s3_bucket_public_access.py)
- `hypothesis`: **principal P can perform action A on exact owned resource R through path T despite expected boundary B**; specify necessary policy/network/token/deployment predicates and known defeating controls. Keep unsupported predicates unknown. `DependsOn`/`RelatedTo` and graph edges are candidate relationships, not causal proofs. [Metadata relationships](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/check/models.py); [policy-centric limitations](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/aws/services/iam/lib/privilege_escalation.py#L6-L15)
- `validation_step` / `chain_edge`: owner/high versus low/anonymous contexts; intended result; exact action/resource grant; channel and declared API-call/retry/cost budget; baseline/test/negative-control hashes; observed effect; replay; unresolved constraints; cleanup before/after and receipt. States should include imported-lead, hypothesis-ready, permission-blocked, inconclusive, refuted-in-this-context, effect-observed and validator-eligible. A generic PASS or scan completion cannot close all deeper edges. [Setting-versus-result example](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/azure/services/storage/storage_blob_public_access_level_is_disabled/storage_blob_public_access_level_is_disabled.py)

**D. Prioritization, continuation and implementation recommendations**

- Prioritize **specific reachable boundary + plausible controlled effect + adequate evidence**, not total FAIL count or static severity. Favor unintended read/write on intended-private owned resources, effective role/trust transitions, exposed identity-connected workloads and concrete deployed artifacts. Keep a parallel posture queue for logging/encryption/resilience gaps. Static severity and relationships are useful ranking inputs only. [Severity/relationship model](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/check/models.py)
- Continue investigating a supported edge **without a preset depth/hop ceiling** while the explicit written scope, ownership, methods/actions, budgets, execution channel and cleanup cover it. A new tenant/resource/action or sensitive-data class outside those grants becomes an explicitly unresolved edge, not permission to widen the hunt. There is no automatic transition from Prowler's graph/policy relationships to execution. [Graph inputs are inventory plus findings](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/README.md#attack-paths); [transitive policy limit](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/aws/services/iam/lib/privilege_escalation.py#L6-L15)
- For BugVault's first implementation, choose an **offline import/plan/record/verify workflow**, not an SDK runner. Add fixtures for CSV and OCSF schema/version differences; PASS/FAIL/MANUAL/muted; account aggregate versus resource result; missing resource names/UIDs; duplicate files and repeated scans; changed check versions; Azure subscription versus tenant; GCP API/permission/organization gaps; default inventory omissions; malicious imported strings and unexpected secret-bearing metadata. Test that imports never send traffic, resolve extracted endpoints, validate credentials, invoke fixers or auto-promote findings. [Format basis](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/reporting.mdx); [UID caveat](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/lib/outputs/finding.py#L575-L598); [inventory limitation](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/docs/user-guide/cli/tutorials/quick-inventory.mdx)
- Preserve the current BugVault distinction between **scanner lead**, hypothesis, controlled effect and confirmed reportable finding. A future cloud skill should hand evidence to existing access-control/IDOR, SSRF, upload, takeover or authentication owners as appropriate; Prowler research adds no live executor, cloud connector, enforcement guarantee or authorization grant. Independent validation is necessary because actual Prowler checks range from one setting to action-combination heuristics. [Azure setting-only predicate](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/azure/services/storage/storage_blob_public_access_level_is_disabled/storage_blob_public_access_level_is_disabled.py); [IAM heuristic](https://github.com/prowler-cloud/prowler/blob/a5fd2d7eda90e9d59e0c4bfc0c74284b47529694/prowler/providers/aws/services/iam/lib/privilege_escalation.py#L466-L517)

### Gaps

- These ladders are **planning recommendations**, not tested procedures or claims of a real vulnerability. No campaign rules, owner accounts, resource IDs, receiver, cloud credentials or live execution path were supplied or used. This research therefore supplies evidence-backed work items and does not fabricate target results. The only concrete detector behaviors asserted are in the pinned sources cited above.
- No credential-use, key retrieval, exploit, privileged mutation, third-party receiver or cloud API budget enforcement has been implemented or authorized by this note. A live assessment needs separately reviewed execution capability; an offline importer does not supply it. Optional Prowler mutating/credential-validation behaviors are precisely why this separation matters.
