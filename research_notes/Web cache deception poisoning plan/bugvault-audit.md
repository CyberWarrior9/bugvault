# Web cache poisoning and deception — BugVault local audit (2026-11-16)

## 1. What is installed, captured and proposed

### Takeaway

E3 is a design entry, not an installed cache hunter. BugVault has useful source-qualified traffic records and a native response-header map, but the normal HAR/Burp projections intentionally discard raw cache-header values; no present component determines a cache key, variant, storage event, serving layer or cross-principal cache effect. [Plan 3](../../plans/plan3.md#L321-L329) · [skill routing](../../recon/skillmap.py#L18-L45) · [store](../../recon/store.py#L70-L126)

### Cited Findings

- **Current checkpoint, not older totals.** The final 2026-11-16 cloud checkpoint reports **26 skills** (8 guides, 18 hunts) and **694 tests run, 2 skipped, 0 failures** on Python 3.15.2; the 674-test/25-skill figures and the 24-skill invariant checkpoint in the same handover are historical. This audit did **not** run the suite. No live campaign, target authorization or connected browser-control tools are supplied. [Handover, earlier and current checkpoints](../../Handover.md#L3-L9) · [Handover, latest verification and missing pilot](../../Handover.md#L524-L545) · [skill inventory test](../../tests/test_recon_skills.py#L103-L113) · [browser prerequisite](../../.claude/skills/scope-policy/references/browser-workflow.md#L24-L26)
- **Design lineage.** Superseded `plans/plan3.md` describes E3 poisoning by unkeyed input, reflected content and a second-fetch `x-cache: HIT`, fat GET and header/key variants; deception by private pages with static-looking suffix/path variants fetched anonymously after a canary account; it asks for cache-status tracking in the observer and lists `hunt-cache-poison` in a *mind-hunt-to-plan* table, not as an installed folder. `plans/plan4.md` puts E3 at L2 + CDN-profile reconnaissance. These are proposed mechanisms, not tests, a validated cache engine or an implemented CLI. [Plan 3 status](../../plans/plan3.md#L1-L10) · [E3](../../plans/plan3.md#L321-L329) · [plan-only skill mapping](../../plans/plan3.md#L538-L557) · [Plan 4 category](../../plans/plan4.md#L151-L157)
- **Actual routing and hint distinction.** `recon/skillmap.py` has no cache class/skill, `recon/catalog.py` lists the 18 installed hunts and does not list a cache ledger, and `recon/score.py:applicable_classes()` never seeds a cache-specific class. `recon/fingerprint.py` tags CloudFront from `x-amz-cf-id` and emits `pack:cache-keys` with a suggested check; `race.py` also notes a `cache-control-unseen` response-header hint. Neither establishes an observed cache engine/key/layer or a cache security finding. [skill map](../../recon/skillmap.py#L18-L45) · [catalog](../../recon/catalog.py#L14-L61) · [coverage seeding](../../recon/score.py#L157-L236) · [fingerprint hint](../../recon/fingerprint.py#L30-L42) · [pack hint](../../recon/fingerprint.py#L120-L124) · [race signal](../../recon/race.py#L205-L218)
- **Source/import provenance.** `source_imports` deduplicates on `(source, original-byte SHA-256, labelled import context)`; `asset_provenance` retains asset/import/record index/basis; `observation_captures` retains a capture key and context. A captured endpoint observation stores method, account, parameter buckets, status and source; the context adds role/tenant/workflow, import ID/entry index/path and CSRF metadata. `endpoint_operations` preserves method and `endpoint_variants` exact path plus *sorted query names*; URL query **values and order are not kept in variants**. [store schema](../../recon/store.py#L42-L126) · [import/observation methods](../../recon/store.py#L266-L355) · [endpoint creation](../../recon/pipeline.py#L93-L135) · [report comparison groups](../../recon/report.py#L91-L124)
- **HAR normalized projection.** `import_har()` labels each import with account/role/tenant/workflow and `captured-real-traffic`; ordinary endpoint observations keep query/body **names**, limited non-sensitive ID-shaped values, auth presence, response status, CSRF request/Set-Cookie *metadata*, and if present a SHA-256 of HAR `response.content.text` (not a decoded wire-body or current cache proof). It does **not** persist ordinary response bodies or raw response header name/value pairs; the original HAR is read and hashed, not copied as a raw transcript by this import. The optional `--script-bodies` path stores captured JS/map body bytes, length/cap completeness and basis `captured-har-body`, but calls `record_request(..., [], {})`, so even there **cache response-header values are absent**. [HAR contract](../../recon/har.py#L1-L17) · [import and script exception](../../recon/har.py#L90-L154) · [ordinary observation](../../recon/har.py#L158-L201) · [report caveat](../../recon/README.md#L642-L646)
- **Burp import normalized projection.** Offline XML/JSON/raw-request parsing reads the operator's source bytes (up to its caps) and computes import identity, but the observation records header/cookie *names* and ID-like input values, not header/cookie values. It stores response body bytes and completeness as `imported-burp-capture`; `resp_headers` contains names mapped to **`(len N)` placeholders**, including `Cache-Control`, `Age`, `Vary`, `X-Cache`, `Set-Cookie` if present. It also stores request body bytes when present and retains the exact URL in the `requests` row; the broad documentation slogan “values never stored” applies to header/cookie values, **not** request bodies or URL queries. The source raw export can still contain private values and must be protected separately. [Burp importer contract](../../recon/burp.py#L1-L17) · [parser/caps](../../recon/burp.py#L34-L54) · [field buckets](../../recon/burp.py#L174-L224) · [response placeholders/payload](../../recon/burp.py#L241-L348) · [privacy regression](../../tests/test_recon_imports.py#L56-L110)
- **Native `recon send` and stored responses.** `ScopedClient` stores a response status, `hmap={lowercase name: value}` from the HTTP library, body SHA-256/length and body bytes under `.recon/bodies/`, completeness/basis `target-http`, URL, method, purpose and an internal `request_id`. The sent request stores **header names only**, and optional nonempty request body SHA-256/length/content type and bytes; `send` prints the live response header map and request ID. Thus raw native *header values in the map* are available for cache analysis, unlike imported Burp/HAR values, but neither the original header casing/order/duplicates nor a byte-exact HTTP transcript is preserved; duplicate names can collapse in the dict. Native sends do not attach the HAR-style account/role/tenant/workflow labels automatically. [network capture](../../recon/net.py#L67-L78) · [recording and header-map conversion](../../recon/net.py#L178-L188) · [store schema/body/capture](../../recon/store.py#L70-L97) · [store request/response access](../../recon/store.py#L469-L525) · [CLI output](../../recon/cli.py#L745-L779)
- **Response IDs and fact limits.** `recon responses` enumerates internal stored record IDs, method/URL/status/completeness/basis. `fact check` can test status, recorded-header presence/exact value and raw UTF-8 body marker on a *specific* stored response; incomplete or encoded bodies and tampered/missing data can be inconclusive/stale. These predicates **do not** prove hit/miss truth, key equality, origin bypass, cache causality or disclosure. Imported Burp captures also create internal `requests.id` records with a clearly different basis; these IDs must not be represented as native `target-http` send IDs. In particular, Burp's placeholder header values cannot support a meaningful cache-header `header_equals` check. [response listing](../../recon/cli.py#L358-L369) · [predicates and evaluation](../../recon/factcheck.py#L19-L56) · [snapshot/byte checks](../../recon/factcheck.py#L101-L142) · [header and body logic](../../recon/factcheck.py#L183-L221) · [imported basis](../../recon/burp.py#L313-L344) · [cloud's strict native-ID pattern](../../recon/cloud.py#L391-L412)
- **Other sources and blind spots.** Scanner adapters keep surface URLs/methods and selected reported tech/status, not HTTP header/body exchanges or scanner verdicts as findings; synthetic runtime API replies are mocked, not proof of backend/cache access. Static `.css`-looking deceptive paths are dropped by `Recon.add_endpoint()` as static even though the *stored request/response* may exist. Endpoint-family grouping normalizes ID-shaped segments, strips trailing slashes and omits query values; its exact variants still reduce query to sorted names, so neither family nor variant is a valid cache-key equivalence oracle. Scope matching additionally decodes/normalizes paths for authorization; a proposed encoded path must be checked against the exact granted URL, not assumed covered because another spelling was. [scanner subset](../../recon/ingest.py#L1-L21) · [scanner projection](../../recon/ingest.py#L88-L141) · [mock runtime limit](../../recon/README.md#L650-L659) · [static and key helpers](../../recon/extract.py#L22-L86) · [endpoint static exclusion](../../recon/pipeline.py#L93-L107) · [scope canonicalization](../../recon/campaign.py#L275-L289) · [scope check](../../recon/campaign.py#L411-L435)

### Inferences

- A future offline cache reader should index **stored request/response records as well as observations**, otherwise `.css` deception routes, non-API pages and unlabelled native traffic vanish; it should bind any imported record by import ID, entry index, source hash and basis rather than promote its internal row ID to a native send. [static exclusion](../../recon/pipeline.py#L93-L107) · [Burp receipt context](../../recon/burp.py#L333-L344) · [store provenance](../../recon/store.py#L104-L126)
- Cache behavior needs an *exact request/representation variant*, not an endpoint family: scheme/host/port, original path (including encoding/case/suffix), complete ordered query and duplicates, method, selected header presence/value fingerprints, cookie/auth state, content negotiation, context labels and response timestamps. The current variants and native header-name-only request log cannot reconstruct these retrospectively; mark them unknown rather than infer. [variant identity](../../recon/store.py#L121-L126) · [request projection](../../recon/store.py#L479-L525) · [endpoint grouping](../../recon/extract.py#L56-L86)
- The cache layer is **unknown absent independent evidence** (owned edge/origin log, explicitly identified response trace, controlled bypass/route contrast); CDN stack tags and a `HIT`-looking string alone are insufficient. The plan's proposed second-fetch `HIT` test should be treated as a lead to controlled pairwise proof, not its semantic acceptance test. [tech hint](../../recon/fingerprint.py#L30-L42) · [pack text](../../recon/fingerprint.py#L120-L124) · [plan E3](../../plans/plan3.md#L321-L329) · [fact warning](../../recon/README.md#L589-L594)

### Gaps

- No installed source retains a **byte-exact, source-qualified request header transcript and repeated response header fields** for all three channels; Burp/HAR raw exports may contain these externally but the normalized records do not. Missing evidence includes actual cache key/config or a key-equivalence observation, `Vary` dimensions, effective policy/TTL, layered edge/shield/origin route, independently seen hit/miss/store decision, stable ordering/freshness, and a bound account/session-to-representation comparison. [native header map](../../recon/net.py#L178-L188) · [HAR projection](../../recon/har.py#L158-L201) · [Burp placeholders](../../recon/burp.py#L313-L344)
- Repository documents disagree in their historical aggregate counts; no test execution was allowed here, so use the latest dated 694/2-skipped checkpoint only as a **documented** result, not as a newly verified run. ## 2. Existing permission, evidence, coverage and finding gates

### Takeaway

The appropriate extension is an **offline evidence worklist** with explicit source, request, context, policy and layer uncertainty, not a new cache-probing executor. Existing scope, channel, budget and finding gates remain separate: a ledger's grant/declared budget can reject an event but never authorize or meter Burp/browser traffic. [scope skill](../../.claude/skills/scope-policy/SKILL.md#L19-L34) · [cloud ledger precedent](../../recon/cloud.py#L1-L5) · [Burp boundary](../../.claude/skills/scope-policy/references/burp-workflow.md#L47-L74)

### Cited Findings

- **Written authorization first.** `scope.json` has exact in/out rules, exclusions, mode, `policy.allowed_methods`, rate, per-run requests/time and persistent campaign request budget; default method set is GET/HEAD and extra methods require active/loud and individual grants. Built-in HTTP checks every hop, refuses Host/proxy overrides and pinned-client proxy use, and does not automatically follow writes. A URL/path from a JS hint or cache-buster is never a scope grant. [campaign policy](../../recon/campaign.py#L456-L480) · [load/validation](../../recon/campaign.py#L506-L567) · [scope instructions](../../.claude/skills/scope-policy/SKILL.md#L6-L18) · [native HTTP enforcement](../../recon/net.py#L139-L157) · [method/redirect behavior](../../recon/net.py#L191-L259)
- **Run plan for every external channel.** Scope-policy requires the program's published permission and source in `scope.json.rules` and a campaign-private `.recon/` plan naming exact targets/exclusions, actions/methods, account-owned disposable resources, rate/concurrency, total cap, window, stops, before/after and cleanup. The dedicated visible browser through Burp is default **only after** control, proxy capture and HTTPS trust are connected/verified; this session has no such control. A separately authorized native run uses the existing `recon send`, not curl or a proxy rewire; operator scanners/Burp replays remain manually scoped/accounted, and a failed check never licenses another route. [scope skill](../../.claude/skills/scope-policy/SKILL.md#L19-L34) · [browser verification](../../.claude/skills/scope-policy/references/browser-workflow.md#L24-L50) · [channel rules](../../.claude/skills/scope-policy/references/browser-workflow.md#L55-L81) · [AGENTS execution limits](../../AGENTS.md#L99-L129)
- **Shared-budget caveat.** Native `ScopedClient` consumes per-instance request/time limits, a persistent campaign attempt counter and per-host pacing; Burp MCP history is a read-only live data source, not a recon-metered sender or response-fact source. External preparation, redirects, retries and controls need manual headroom and reconciliation; stop at 429, challenge/lockout, unexpected effect or cap. `host_pacing` is not an atomic simultaneous-process reservation. No unattended Param Miner/active cache scan or bulk key guessing follows from the design. [native budget path](../../recon/net.py#L49-L65) · [persistent reservation/pacing](../../recon/store.py#L439-L461) · [README limitation](../../recon/README.md#L109-L113) · [Burp handoff](../../.claude/skills/scope-policy/references/burp-workflow.md#L47-L74) · [catalog reference-only paramminer](../../recon/catalog.py#L135-L146)
- **Offline-ledger precedent.** `cloud.py` stores source hash/selector/snapshot, exact operation and source-qualified native (`target-http`) vs `burp:` external IDs; for live-labelled events it checks reviewed rules, mode, method, labelled grant and a **declared** shared budget, copies campaign-local artifacts by hash and verifies stale/tampered source/policy/evidence. Its own comments explicitly deny execution, provider semantics and automatic finding promotion. Upload/authz likewise keep exact contexts, controls, separate lifecycle facts, stops and coarse-coverage conflicts; their gates are not external budget enforcement. A cache ledger can reuse this pattern without copying cloud-resource identity or suggesting a cloud API was tested. [cloud source schema](../../recon/cloud.py#L32-L52) · [source integrity](../../recon/cloud.py#L221-L285) · [record/ID/grant checks](../../recon/cloud.py#L346-L423) · [artifact and policy verification](../../recon/cloud.py#L431-L536) · [upload precedent](../../recon/README.md#L179-L225) · [authz precedent](../../recon/README.md#L142-L176)
- **Coverage is coarse today.** `refresh_coverage()` seeds endpoint classes from `score.applicable_classes()` and service pack hints from fingerprint tags, and `coverage.md` prints `skills_for(class)` beside untested rows. It does not represent cache variant × principal × layer × scenario. `cov` accepts manual status edits and only JS currently has a special coarse-closure block in `cmd_cov`; report sections for CSRF/authz/upload/SSTI/logic/race expose open exact work separately. **Do not** let a generic `cov tested/confirmed/refuted` close untested cache variants. [coverage seeding](../../recon/pipeline.py#L225-L239) · [coverage status setter](../../recon/store.py#L370-L395) · [CLI special-case](../../recon/cli.py#L135-L147) · [report tables](../../recon/report.py#L300-L449)
- **Finding gate is necessary but not semantically sufficient.** `Findings.add()` accepts an in-scope URL and generic bug-class string; `lead → confirmed` requires separate replay and negative-control files with different hashes, then impact proof for `impact-proven`; it does not inspect whether the files prove cache serving, privacy or actual source attribution. The validator separately requires real replay, a failing negative control, actual harm/realistic preconditions and chain completeness; a mere status, copied marker, scanner verdict or CDN tag is a lead. The older plan3 seven-question/body-diff gate is a **design document**; today’s live code uses the finding artifact gates plus validator judgment, not an automatic cache classifier. [findings schema/add](../../recon/findings.py#L32-L84) · [finding add](../../recon/findings.py#L147-L183) · [move/artifact gates](../../recon/findings.py#L209-L247) · [validator/reportability](../../recon/prompts/validator.md#L18-L58) · [plan3 gate](../../plans/plan3.md#L518-L534)
- **Data safety.** Campaign `.recon/` may hold raw downloaded bodies/headers and credentials; HAR/Burp originals are outside their normalized privacy guarantees. The cloud plan distinguishes protected raw evidence from a value-free/redacted outward projection and rejects a public identifier or a synthetically owned marker as automatic impact. A future cache export should expose hashes, selectors and classifications by default, not session cookies, sensitive URL query values or private body text. [README private-data warning](../../recon/README.md#L648-L660) · [AGENTS provenance/provider minimization](../../AGENTS.md#L85-L95) · [cloud plan source/privacy rule](../../plans/cloud-misconfiguration.md#L41-L49) · [cloud finding caution](../../plans/cloud-misconfiguration.md#L69-L75)

### Inferences

- Proposed `cache` configuration should be **fail-closed evidence readiness**, not a standing traffic grant: require program URL/rules review, allowed cache case families and exact methods/origins, scoped owned A/V labels, a positive shared declaration across native/Burp/browser/scanner, per-host/time/TTL/object caps, stop/resume/cleanup owner, and independent execution approval for any actual sends. A separately protected raw header artifact may be opt-in after minimization review. [campaign validators](../../recon/campaign.py#L74-L115) · [cloud grant wording](../../recon/campaign.py#L195-L211) · [scope skill](../../.claude/skills/scope-policy/SKILL.md#L19-L34) · [privacy boundary](../../recon/README.md#L648-L660)
- Prefer **no automated live cache poisoning** in the first slice. For a hypothetical later pilot, a purpose-built benign marker should touch only a disposable owned page/object and the specified shared cache partition; a purge/expiry verification and stop condition matter because a cache mutation may persist beyond the request that made it. The existing upload stop/cleanup and cloud before/after/control patterns are useful models, not a license to mutate shared production caches. [upload lifecycle gates](../../recon/README.md#L203-L225) · [cloud canary control roles](../../recon/cloud.py#L439-L459) · [external accounting](../../.claude/skills/scope-policy/references/burp-workflow.md#L60-L71)

### Gaps

- There is **no supplied campaign `scope.json` or written authorization** for cache-specific path/header/query variations, cache mutation, anonymous replay, victim-context navigation, purge, scanners or a shared CDN; Handover reports zero configured campaigns. No live case or specific cache-control behavior can be asserted. [Handover campaign status](../../Handover.md#L46-L51) · [scope requirement](../../.claude/skills/scope-policy/SKILL.md#L6-L11)

## 3. Staged offline build and acceptance contract (proposal; nothing implemented here)

### Takeaway

Implement source fidelity and exact-context evidence before any case classifier; then a bounded, offline poison/deception ledger and owned-loopback semantic contrasts. Only after these pass should code be wired into skill, coverage and status surfaces or a separately approved live pilot considered. No `recon cache` command exists in the inspected CLI; the steps below name **future file/function work**, not runnable invocations. [CLI command registry](../../recon/cli.py#L787-L807) · [existing offline-ledger pattern](../../recon/README.md#L17-L50) · [local-test convention](../../Handover.md#L438-L450)

### Cited Findings

- **Stage 0 — define the contract, no traffic.** Document two proposed classes/case families (`cache-poisoning` and `web-cache-deception`, names subject to review): the test unit should be exact origin + raw-path/query + method + selected request headers/representation + opaque principal/session context + hypothesized layer/key/TTL + case/variant. Distinguish *candidate*, *observed header/body fact*, *attributed cache store/serve*, *cross-context effect*, *validated impact* and *blocked/inconclusive/negative*. Include source kind and hash, capture completeness, request count provenance, policy snapshot and unknowns. No current schema or plan3 E3 entry supplies that full contract. [E3 design](../../plans/plan3.md#L321-L329) · [store exact variants limit](../../recon/store.py#L117-L126) · [cloud source/event/policy pattern](../../recon/cloud.py#L32-L52) · [cloud plan exact-context principle](../../plans/cloud-misconfiguration.md#L219-L227)
- **Stage 1 — protected offline capture adapter.** A proposed `recon/cache_capture.py` should ingest **only operator-designated, campaign-local** Burp/HAR request/response pairs with bounded bytes, source hash, per-entry selector, capture time, completeness, HTTP version if available, and lossless *cache-relevant* response header occurrences (`Cache-Control`, `Surrogate-Control`, `Vary`, `Age`, `ETag`, `Date`, `Expires`, `Via`, `Warning`, vendor cache-status) and presence/value fingerprints of intentionally selected request dimensions. Store raw values only in private restricted artifacts if explicitly approved; by default expose normalized, redacted/hash-only metadata. Do not overwrite the existing HAR/Burp value-free projections or infer a missing header from an incomplete capture. Native reads can reference `requests.id`/`response_capture` and its header-map limitations; imported Burp IDs retain `imported-burp-capture` and source labels. Proposed edits: additive `recon/store.py` tables/migration plus optional `recon/har.py` and `recon/burp.py` extraction hooks (or a separate adapter), **not** new network calls in `net.py`. [HAR paths](../../recon/har.py#L90-L200) · [Burp parser/import](../../recon/burp.py#L227-L348) · [native storage](../../recon/store.py#L469-L525) · [cloud imported-source integrity](../../recon/cloud.py#L221-L285)
- **Stage 2 — offline ledger and gap-first review.** A proposed `recon/cache.py` should reconcile stored captures into distinct per-origin, per-path/ordered-query, method/representation, A/V/anonymous/session and layer candidates, deduplicate replayed imports without collapsing genuinely different responses, and retain unsupported, truncated, stale and unlabelled records as gaps. An offline plan should list the minimum controls and permission blockers rather than generate a payload list or dispatch traffic; a record path should accept only source-labelled native IDs or external refs, bounded hash-bound evidence and declared request counts, reject cross-campaign/stale context, and never call `Findings.move()`. A status/verification view should rehash raw source, event and policy snapshots, name open variants and coarse conflicts. This adapts existing `CloudLedger.sync/plan/record/status/verify` and upload/authz patterns; **no command names or JSON schema are claimed installed**. [cloud sync/paging](../../recon/cloud.py#L262-L285) · [cloud record provenance/grants](../../recon/cloud.py#L346-L423) · [cloud verify](../../recon/cloud.py#L489-L536) · [authz worklist](../../recon/README.md#L142-L176)
- **Stage 3 — owned-loopback semantic fixtures.** Proposed `tests/test_recon_cache.py` (offline parser/ledger) and `tests/test_recon_cache_lab.py` (two or three tiny `127.0.0.1` HTTP servers: edge, optional shield, origin) should have deterministic layer-local logs, stable keys, separately counted store/serve/origin requests and isolated owned A/V/anonymous contexts. Follow the repository's loopback-only cloud fixture precedent; it is a simulation, **not** real CDN/browser behavior. The vulnerable poisoning fixture has an origin that varies an inert owned marker on one query/header input, while an edge key omits just that input: cold clean baseline → A's distinct marker request → A replay/edge store → independent clean B/anonymous request (no marker in its request) receives A's marker; control adds the determinant to the key or disables caching, and a normal public cache positive control proves the cache actually works. Do not use executable payloads. [owned lab pattern](../../tests/test_recon_cloud_lab.py#L14-L68) · [lab's before/control/cleanup](../../tests/test_recon_cloud_lab.py#L69-L123) · [plan3 mechanism](../../plans/plan3.md#L321-L329) · [body-byte limit precedent](../../recon/factcheck.py#L183-L221)
- **Deception and layers in the same small lab.** An origin serves an intended-private, V-owned synthetic marker at a static-looking `.../settings/nonexistent.css` and separately handles ordinary static assets. The vulnerable edge mistakenly keys/caches the private response without the auth determinant; V's visit primes it, then an independently authenticated A/anonymous request retrieves V's marker, while origin-side owner log shows no corresponding A/anonymous private read. Fixed controls reject/cache-bypass private/no-store content or normalize the deceptive route safely; public static and private non-cacheable positive/negative controls ensure that a `200` or suffix alone does not count. Add a two-cache variant where only shield stores versus edge serves and require attribution to the actual layer from each cache's log, not a guessed `Via`/`X-Cache`. Include isolated `Vary` variants and a 304/no-body case so status/header-only matches cannot masquerade as cross-context content. [plan3 deception examples](../../plans/plan3.md#L321-L329) · [body/negative completeness](../../recon/factcheck.py#L195-L221) · [validator's independent control](../../recon/prompts/validator.md#L18-L36) · [loopback attribution precedent](../../recon/README.md#L203-L225)
- **Stage 4 — wiring only after evidence contract passes.** Add a cache-ledger row/class seeder in `recon/score.py` and/or `Recon.refresh_coverage()` that labels response-backed candidates separately from CDN *hints*; avoid excluding non-CDN application/reverse-proxy caches and avoid seeding every `.css` URL as a vulnerable endpoint. Add skill mapping in `recon/skillmap.py`, a single `.claude/skills/hunt-cache-poison/SKILL.md` with scope-policy, minimal controls and the existing validator/reportability gate, explicit partial/offline inventory in `recon/catalog.py`, bounded section/open gaps and coarse-closure conflicts in `recon/report.py`, and only then CLI/parser handlers in `recon/cli.py` (document actual implemented verbs at that time). Add `tests/test_recon_skills.py` routing/catalog/frontmatter/CLI guards; `tests/test_recon_imports.py`, `test_recon_factcheck.py` and scope/boundary tests for truncated/encoded/private-header and scope/ID failures.
