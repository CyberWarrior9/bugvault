# JS bundle hunt — bounded inventory and offline lead ledger

Read `scope-policy`, the campaign's published rules and `coverage.md` before target tests. The dedicated visible browser through Burp is the default live path; a standing campaign execution plan can also allow scoped native requests/operator-run scanners within the written scope/rate/budget. The JS ledger itself sends **no traffic**. A separate `recon run` may execute queued `jsretained` GET jobs only under active mode, `program_url`, `js.rules_reviewed` and a positive `js.stale.max_old_assets` (default **0**). Do not use an importer, Burp send or a shell client to bypass a failed check. If browser control or a selected authorized campaign is unavailable, do not claim a live test.

## Inventory → test card → destination

1. `python3 -m recon js sync <campaign>` indexes **stored** script/map/HTML bodies, recognized build IDs and bounded asset edges. `python3 -m recon js status <campaign>` lists incomplete bodies, unresolved/traffic-only assets, stage events and ranked leads; `js verify` checks stored hashes. Missing chunks, ambiguous build membership, synthetic UI calls and imported captures are **gaps**, not negatives. `complete=false` remains intentional while stages are not graded end to end. A source map alone is never reportable.
2. `python3 -m recon js builds <campaign>` retains identified builds. `js diff <campaign> --origin https://app.example.test` shows new/removed operations; `js plan <campaign> --lane stale --packets` ranks `zombie` and `js_only` references. `js show <campaign> js:<lead-key>` displays sightings, packet, rung receipts and destination finding stages. `js export <campaign> --kind packets --out <campaign-local-path>` emits value-free work cards; the file may still contain private program paths and belongs in private campaign storage. No export is a request script.
3. A packet needs a resolved operation, method, transport, **names** of auth carriers and fields, labelled real account/role/tenant/workflow capture, operator-owned object binding where applicable, a distinct negative control, and an impact ceiling. `base-unresolved`, signed/encrypted or unbound role/object cases stay blocked. Never print or export header/cookie/token **values**. Public-by-design keys are never-submit; unsigned JWT claims are unverified hints. No credential validation outside the written program scope.
4. For a retired operation record each rung separately with `js record <campaign> <lead-key> --rung <current-live|version-sibling|archived-chunk|removed-op> --outcome <blocked|inconclusive|HTTP-status> [--response <stored-id>] --reason '...'`. A 404 closes only that asset/operation observation; a 200 is **live-observed**, not server-side authorization. `js pair <campaign> --low-response <id> --owner-response <id>` records paired J17 **asset delivery** with complete stored responses at the same URL and distinct labelled operator sessions (anonymous low is allowed). `served` does not imply non-public source or a finding; `denied` is a delivery observation, not endpoint authorization.
5. `js record <campaign> <lead-key> --state handed-off --ref cov:<asset-id>:<class>` needs an existing destination row. Or use `finding add ... --lineage js:<lead-key>` to attach a *lead* to a destination finding; only the destination validator may confirm it with replay, distinct negative control and demonstrated impact. Use `hunt-access-control` for function/field policy, `hunt-idor` for object swaps, `hunt-csrf` for cross-origin actions, `hunt-xss` for DOM execution and `hunt-file-upload` for signed-storage flows. `js record` cannot set `tested`, `negative` or `confirmed`. Do not close a coarse `js-bundle` coverage row while `js status` has gaps.

## Safe acquisition and stop rules

Collect only in-scope script/map URLs referenced by authorized content, with existing per-origin and body caps; guessed maps remain loud-only. Imported HAR URLs never auto-refetch, including with `--script-bodies`; that option stores only explicitly exported response bodies with honest completeness. An out-of-scope federation remote, import-map entry or precache URL becomes intel only. Query-bearing asset URLs require review rather than silently stripping tokens and fetching a different path. `jsretained` uses previously captured old paths, no endpoint probes. A 429/5xx stops retained fetching for the host; after reviewing rules and budget, `js resume <campaign> --origin <origin> --reason '...'` records the review and requeues eligible skipped work, but **does not send**. A separate approved `recon run` is required. No M6 `jsprobe`, provider-secret checker, M7 optional scanner importer or bulk extraction is implemented.

## Family routing and never-submit limits

The ledger has conservative **partial** J01–J17 static candidates, not complete syntax/dataflow coverage. J01/J02/J12/J15 stale or privileged operations → function policy with test accounts and a negative control, not bulk enumeration; J03 Next actions → captured owned action, disposable objects for writes; J04/J05 GraphQL/RPC → captured operation and field policy; J06 secret → format-only classification, no assumed validity; J07 map alone → never-submit; J08 client gate → verify the *server* gate; J09 client flow → marker execution in the browser; J10 host → scope check before contact; J11 version → advisory prerequisites, not exploit proof; J13 auth/crypto → captured carrier only; J14 signed storage → upload lifecycle; J16 WASM/dynamic code → explicit extraction gap; J17 chunk/map/old-build delivery → paired roles plus non-public-source review. See `plan_js_bundle_hunt.md` §6.2 for the intended full taxonomy and §11 for acceptance cases not yet met.

Never publish pre-fix source, internal package names or raw secrets; do not test third-party hosts, buy/share accounts, attempt credential spraying or download bulk data. If a browser, scope/method grant, labelled test account or budget is missing, leave the case blocked/inconclusive and preserve the lead.
