# Trace Remote Inputs, Prove Server Execution

**Decision:** Hunt remote code execution (RCE) as the *terminal result of a traced, attacker-reachable server-side sink*, not as a generic property of an endpoint or a scanner alert. Four maintained GitHub repositories supply a testing vocabulary, source-to-sink analysis, a class taxonomy, and code-review leads; four separately published pages explain the behavioral boundaries that most often cause false claims. The operating sequence is written authorization, source-qualified mapping, owned-lab discrimination, offline evidence tooling, and only then an optional, separately approved, minimal live observation. BugVault already inventories several entry paths and preserves replay/control artifacts, but it has **no installed RCE-specific route, command-injection or deserialization ledger, or general execution-proof assessor**; [the existing draft](../plans/rce.md) is a proposal, not an implementation ([routing](../recon/skillmap.py); [catalog](../recon/catalog.py)). This report is a plan, not a test: **no campaign, target, account, request, code-execution attempt, or vulnerability was validated here**. It deliberately provides no attack payloads or exploit-execution instructions.

## Eight input-to-sink paths matter more than an “RCE endpoint”

For this plan, **RCE means an attacker with the program-defined remote role can cause server-side code or OS-command execution outside the application's intended, authorized behavior**. Legitimate admin jobs, client-side JavaScript, a server merely invoking its normal fixed command, template arithmetic, XML entity resolution, deserialization attempts, and fetched URLs are **not automatically RCE**. Even a server-side execution primitive is a vulnerability only after an attacker-controlled trust boundary and relevant preconditions are established. Model each candidate as **exact entry operation and actor → controlled field/bytes → validation, decoding, storage or queue transition → trigger and worker → deployed interpreter/process/serializer/parser/runner sink → observable effect and executing authority**. Each edge carries direct-versus-inferred status, source file/line or import/request/response/log ID, SHA-256, capture completeness, date, scope revision and missing preconditions; fork a trace when one value has multiple consumers. Current input imports preserve useful context but do **not** trace server-side transitive callers or certify sink reachability ([recon/README.md](../recon/README.md); [recon/fields.py](../recon/fields.py); [recon/jsledger.py](../recon/jsledger.py)).

The order below is a **review priority for BugVault's present mapping leverage and safe discrimination**, not a frequency estimate or authority to test a production sink. “First discriminator” is an offline or owned-lab question; a “live” boundary always means a *separate* written campaign grant and operator decision. A low-ranked path becomes urgent when a direct source trace and an owned, attributable effect exist.

| Priority and candidate pathway | Where to look; what changes the decision | Current owner / boundary |
|---|---|---|
| **1 · Process invocation and argument injection** | Export, report, image conversion, mail, search, backup and job options or filenames → shell construction **or** argv/options of a subprocess. Seek authorized server source or owner-provided argv/worker logs distinguishing literal data from interpreted arguments; a status, latency change or accepted name is not execution. | No command-injection ledger; proposed sink inventory. `hunt-file-upload` may identify a processor leg, but live metacharacter filenames and process-argument cases are **review/lab-only** under its current rules ([upload skill](../.claude/skills/hunt-file-upload/SKILL.md); [PortSwigger](https://portswigger.net/web-security/os-command-injection)). |
| **2 · Server-side template injection** | User-editable email/CMS/report text, delayed notifications and exports → template source, string-to-template feature or include selection → render context/helper. Compare raw *server* responses and the actual later render surface with literal and harmless evaluation controls; a DOM-only value or engine-like syntax is a weaker observation. | `recon/ssti.py` and `hunt-ssti` already classify inert arithmetic on exact surfaces; **they do not prove code execution or a particular engine** ([SSTI skill](../.claude/skills/hunt-ssti/SKILL.md); [OWASP Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Template_Injection_Prevention_Cheat_Sheet.html)). |

No production build trigger, published exploit, credential derivation or runner registration by default ([vulnerability intel](../recon/vulnintel.py); [access-control skill](../.claude/skills/hunt-access-control/SKILL.md); [cloud skill](../.claude/skills/hunt-cloud-misconfig/SKILL.md)). |

**Triage score, not severity or permission:** give each *exact path/context* 0–3 points for direct input-to-sink evidence, 0–2 for attacker-role reachability, 0–2 for verified deployed version/configuration, 0–2 for a safe independently attributable observation channel, and 0–1 for fresh corroborating capture or owner confirmation. Unknown earns zero; contradictory evidence reclassifies or blocks rather than subtracting toward “safe.” Review 7–10 first, 4–6 after a named missing fact arrives, and 0–3 as a parked, source-labelled hypothesis. A written exclusion or unapproved second hop **vetoes live work at any score**. Revisit only when a new captured route/role, source trace, release/configuration, processor/runner, authorized receiver, owner log, scope rule or resolved cleanup changes a recorded precondition; do not recycle the same static signature or treat a single negative on one variant as endpoint-wide coverage. This is a **proposed BugVault scheduling heuristic**, not a measured detection model ([existing scoring](../recon/score.py); [validator](../recon/prompts/validator.md)).

## Six gated phases move from inventory to a reportable effect

The phase gates make the **when** explicit. P0–P3 are offline or isolated owned-loopback engineering; P4 is optional, supervised and **not authorized by completing P3**. P5 applies the existing validator even when no live execution proof is possible. Each phase produces a durable private artifact rather than an unrecorded impression. The gates below adapt the [integration research](../research_notes/RCE%20hunting%20plan%202026/bugvault_integration.md) to BugVault's [scope policy](../.claude/skills/scope-policy/SKILL.md) and [finding lifecycle](../recon/findings.py).

| Phase | Deliverable | Gate and acceptance criterion |
|---|---|---|
| **P0 · Authority and proof contract** | Written campaign scope/exclusions, exact allowed methods/roles, traffic/time/byte/object caps, channel/second-hop/receiver limits, disposable owned accounts/resources and cleanup owner; a glossary separating exposure, evaluation, processing, lookup, and execution. | **No target contact** until published rules and `scope.json` match the intended action; execution proof needs **specific written approval**, not merely an upload or POST method grant. Missing program, receiver or connected observer means **offline/lab-only**. Confirm that no real-user data, destructive test or persistent artifact is required ([scope policy](../.claude/skills/scope-policy/SKILL.md); [AGENTS.md](../AGENTS.md)). |
| **P1 · Source-qualified graph** | One record per exact URL/method/input location/content type/account/role/tenant/workflow and trigger; linked storage/encoding/validation, worker/config/version, sink, privilege and outcome nodes, with direct/inferred edge provenance and unknowns. | **Gate A:** deduplicate repeated imports without pooling accounts, variants or consumers; retain source IDs/hashes and flag stale scope/source/config. Serialized-looking fields, frontend eval, status codes and guessed processor names remain leads. No indiscriminate RCE coverage row ([recon/README.md](../recon/README.md); [skill map](../recon/skillmap.py)). |
| **P2 · Lab-first mechanism discrimination** | For implemented paths, isolated loopback fixtures with a working normal operation, safe deliberately vulnerable case, fixed/matched negative and, if delayed, attributable worker record; a small candidate score and missing-precondition log. | **Gate B:** run only inert marker/nonce effects on owned disposable objects; prove the test can distinguish server-only execution from reflection, parsing, normal conversion, client rendering and bare callback. | **P3 · Offline tooling and adversarial acceptance** | **Proposed**, not installed: a shared evidence manifest/assessor (`recon/execproof.py`), source-qualified command-injection and deserialization sink ledgers (`recon/cmdi.py`, `recon/deser.py`), and `hunt-rce` as a terminal-proof guide. The **evidence ladder** is narrower than the often-used “payload caused an anomaly” shortcut. A **lead** is a static reference, query/rule hit, serialized format, version fingerprint or potential sink. **Reached-sink** identifies the specific server caller/worker and the attacker-controlled value crossing that boundary, ideally in authorized source or owner telemetry. **Behavior observed** names exactly what occurred—template arithmetic in a raw server response, deserialization/lookup, image conversion, a latency difference or a correlated callback—without calling it code execution. **Server execution verified** requires an approved *inert, one-shot, nonpersistent* server-only effect through that reachable path, with output or owner-provided worker evidence **not already supplied as the claimed result in the request**, a healthy baseline, fresh replay with another nonce and a matched negative whose assertion fails. If owner-side attribution is unavailable, a callback, delay, HTTP 200 or reflected marker does not bridge the gap; park it. **Impact proven** adds only an authorized, narrowly owned consequence and its independent readback; severity follows the actual authority/boundary, not the RCE label or a demanded read of system files ([PortSwigger](https://portswigger.net/web-security/os-command-injection); [Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/standard/serialization/binaryformatter-security-guide); [ImageMagick](https://imagemagick.org/security-policy/); [validator](../recon/prompts/validator.md)).

For every phase, retain immutable **campaign-private** artifacts with SHA-256 and source/capture-fidelity labels: baseline, trigger, fresh replay, negative, optional healthy-workflow/owner log, impact and cleanup. Bind them to exact operation, actor, owned object, sink/worker, policy snapshot, time window and native request ID *or separately labelled Burp reference*; those identifiers are not interchangeable. A byte-presence fact or two distinct file hashes is **not semantic proof**: the existing checker verifies raw status/header/body-byte predicates and marks unsupported encoded/incomplete cases conservatively, while the existing finding transition checks replay/control file presence and distinct hashes, leaving causality to a validator ([fact checker](../recon/factcheck.py); [findings](../recon/findings.py); [response store](../recon/store.py)). Redact tokens, cookies, private documents and any accidental secrets before a model-facing view; do not read credentials, environment dumps, real users' records or cloud metadata merely to increase a claimed severity ([AGENTS.md](../AGENTS.md); [validator](../recon/prompts/validator.md)).

**Stop and preserve evidence** on 429/5xx, challenge/lockout, degradation, unexpected side effects or third-party data, unapproved redirect/second hop, receiver loss, traffic-cap breach, worker uncertainty or failed cleanup. No retry around a control and no fallback to Burp, native HTTP or a scanner after a failed gate. Delete or abort owned test objects, queued jobs and derivatives where the program allows, record a separate readback/retention receipt, and require operator review before resuming. Do not use web/reverse shells, active executable uploads, dangerous deserialization gadgets, memory corruption, archive bombs, long timing probes, credential exfiltration, destructive writes or persistent changes; **existing upload restrictions remain in force unless a genuinely separate written program exception and safety review supersede them** ([upload skill](../.claude/skills/hunt-file-upload/SKILL.md); [scope policy](../.claude/skills/scope-policy/SKILL.md); [AGENTS.md](../AGENTS.md)).

## BugVault already maps entrances, not universal execution proof

**Installed today:** `recon/score.py`, `recon/fields.py`, HAR/Burp/OpenAPI imports and `recon/jsledger.py` assemble input and route leads; `recon/ssti.py` owns evaluation per render surface; `recon/upload.py` separates accepted/stored/processed/served/**executed** facts with an attributable consumer-log requirement; `recon/ssrf.py` correlates bounded callbacks without certifying execution; `hunt-xxe`, `hunt-sqli`, `hunt-access-control` and `recon/vulnintel.py` own their respective starting boundaries ([input and skill routing](../recon/README.md); [SSTI module](../recon/ssti.py); [upload module](../recon/upload.py); [SSRF module](../recon/ssrf.py); [vulnerability intel](../recon/vulnintel.py)). An existing `ssti-exec` chain name is **not** a server-execution fact: its current steps are SSTI and access control, and `chain status` treats a step as proven when its *class finding* reached confirmed, not when code ran ([chain templates](../recon/chain.py)). CodeQL and Semgrep are **external review options for authorized source**, not installed BugVault source-to-sink executors ([catalog](../recon/catalog.py)).

**Proposed new work, explicitly separate:** keep `rce` as a *terminal finding/evidence outcome*, never seed it on every host. Add `command-injection` and `deserialization` **candidate coverage only on a source-qualified sink path**, then a shared `hunt-rce` proof contract that links them with existing SSTI/upload/SSRF/XXE/SQLi lineage. Build the offline assessor and sink inventories after P0–P2, with catalog/skillmap/seeder/coverage/test consistency and no automated promotion. Do **not** copy [the draft's](../plans/rce.md) claim that a callback needs no existing checking: [callback validation](../recon/callbacks.py) already checks approved receivers for several *recorded* evidence flows, but the generic [scoped HTTP client](../recon/net.py) does not prove every URL embedded in a request, and Burp/browser/scanners lack a common pre-send second-hop policy or atomic budget. Equally, adding a `duration_exceeds` predicate alone cannot work: [response storage](../recon/store.py) has no measured per-request duration, so trustworthy capture/baseline/jitter attribution must precede timing assessment ([factcheck](../recon/factcheck.py); [integration note](../research_notes/RCE%20hunting%20plan%202026/bugvault_integration.md)). Treat the draft's suggested system-file/environment reads and upload-bypass depth as **nonrequirements** here; the least-impact, owned effect is the proof target, and the present upload skill's hard limits take precedence ([draft](../plans/rce.md); [upload skill](../.claude/skills/hunt-file-upload/SKILL.md)).

## Conclusion

**The strongest next investment is evidence infrastructure, not an RCE payload library:** preserve exact source-to-worker lineage and teach an offline assessor to reject reflected, client-only and callback-only counterexamples before adding new candidate classes. This lets the existing BugVault entry-path owners continue their narrower work without turning a successful template evaluation, processed file or chained request into a fictitious terminal finding ([integration note](../research_notes/RCE%20hunting%20plan%202026/bugvault_integration.md); [validator](../recon/prompts/validator.md)).

**Limitations and unresolved unknowns:** No written campaign permission, target architecture or authorized server source, owned test accounts, active processor policy, worker logs, deployed versions, connected live browser observer, measured request durations, cross-channel atomic budget, or approved second-hop/receiver plan was supplied; no lab or target exercise was performed for this report. The four repository dates are activity timestamps, **not** verified per-technique freshness, and three of the four selected pages lack a verified per-page date; Microsoft's metadata dates do not certify every passage. Without a safe owner-attributable execution effect and a matched negative, the correct disposition remains **lead, blocked or inconclusive**, not a claim of RCE, severity, or endpoint-wide coverage ([repository research](../research_notes/RCE%20hunting%20plan%202026/github_repositories.md); [page research](../research_notes/RCE%20hunting%20plan%202026/independent_guides.md); [BugVault integration research](../research_notes/RCE%20hunting%20plan%202026/bugvault_integration.md)).
